# ブラウザ操作

ブラウザ操作は、PlaywrightとChromiumを使ってWeb画面を自動操作するn8nノードです。
APIを持たない業務システムへの入力、登録、結果取得、ファイルアップロード、
スクリーンショット取得などを、1つのノード内に複数のStepとして設定できます。

1回の入力Itemに対するすべてのStepは、同じBrowser ContextとPageで上から順番に実行されます。
そのため、Open URL後のログイン状態や画面状態を、後続のFillやClickでそのまま利用できます。

## クイックスタート

以下は、フォームを開いて氏名を入力し、登録結果を取得する最小構成です。

1. ワークフローに**ブラウザ操作**ノードを追加します。
2. **ステップ**で**ステップを追加**を押し、`URLを開く`を選択します。
3. **URL**へ対象画面のURLを入力します。
4. ステップを追加し、`入力`を選択します。
5. **ロケーターの種類**を`ラベル`、**ロケーターの値**を`氏名`にします。
6. **入力値**に`{{$json["name"]}}`を入力します。
7. ステップを追加し、`クリック`を選択します。
8. **ロケーターの種類**を`ロール`、**ロール**を`ボタン`、**アクセシブル名**を`登録`にします。
9. ステップを追加し、`待機`で完了メッセージの表示を待ちます。
10. ステップを追加し、`テキストを取得`で登録番号を取得します。

`テキストを取得`の**出力変数名**を`registrationNumber`にした場合、後続ノードから次の式で参照できます。

```text
{{$json["registrationNumber"]}}
```

## 主な機能

- 1ノード内で複数Stepを順番に実行
- Google Sheetsなどの前段ItemをExpressionで利用
- Role、Label、Text、Test IDなどのPlaywright Locator
- React、Vue、AngularなどのSPAに適した状態ベースの待機
- iframe内の要素操作
- n8n Binary Dataからのファイルアップロード
- PNG／JPEGスクリーンショットのBinary出力
- Step単位のRetry
- 成功／エラーの2系統出力
- 構造化された日本語エラー情報
- エラー発生時のスクリーンショット取得
- Browser、Context、Pageの自動Cleanup

## 実行モデル

- 1回のノード実行につきChromiumプロセスを1つ起動します。
- 入力Itemごとに独立したBrowser ContextとPageを作成します。
- 同じItemのStep間では、Cookie、ログイン状態、Pageを維持します。
- 異なる入力Item間では、CookieやSessionを共有しません。
- 入力Itemは順番に処理されます。
- ノード実行の終了、エラー、キャンセル時にPage、Context、Browserを閉じます。
- Ver.1では、複数のブラウザ操作ノード間でSessionを共有しません。

## ブラウザ設定

**ブラウザ設定**の**設定を追加**から、必要な項目だけ追加できます。

| 設定                                                    |       既定値 | 説明                                                                                            |
| ------------------------------------------------------- | -----------: | ----------------------------------------------------------------------------------------------- |
| ヘッドレス                                              |       `true` | 画面を表示せずにChromiumを実行します。Dockerでは`true`を推奨します。                            |
| ブラウザ起動タイムアウト（ミリ秒）                      |      `30000` | Chromiumの起動を待つ最大時間です。                                                              |
| ページ遷移タイムアウト（ミリ秒）                        |      `30000` | URLを開く操作などのページ遷移を待つ最大時間です。                                               |
| 表示領域の幅                                            |       `1280` | ブラウザ表示領域の幅です。                                                                      |
| 表示領域の高さ                                          |        `720` | ブラウザ表示領域の高さです。                                                                    |
| ユーザーエージェント                                    |           空 | 空の場合はChromiumの既定値を使用します。                                                        |
| ロケール                                                |      `ja-JP` | Browser ContextのLocaleです。                                                                   |
| タイムゾーン                                            | `Asia/Tokyo` | Browser ContextのTimezoneです。                                                                 |
| HTTPSエラーを無視                                       |      `false` | 信頼できない証明書を無視するかを指定します。通常は無効のまま使用してください。                  |
| プライベートネットワークURLを許可（信頼済みサイトのみ） |      `false` | localhostやプライベートIPへの接続を許可します。信頼できる社内サイトに限って有効にしてください。 |
| 最大アップロードサイズ (MB)                             |         `25` | 1回のファイルアップロードで許可する最大Binaryサイズです。                                       |

## ステップ

**ステップ**へ操作を追加し、ドラッグして実行順を並べ替えます。

### URLを開く

指定したURLを開きます。

| 設定         | 説明                                                                |
| ------------ | ------------------------------------------------------------------- |
| URL          | 開くHTTP／HTTPS URL。Expressionを利用できます。                     |
| 読み込み待機 | `読み込み完了`、`DOM構築完了`、`通信が落ち着くまで`から選択します。 |

SPAでは、最初の画面表示に`DOM構築完了`を使い、その後に要素の表示を待つステップを置く方法を推奨します。

### 入力

入力欄へ値を設定します。Playwrightの`fill()`を使用します。

| 設定       | 説明                                                |
| ---------- | --------------------------------------------------- |
| ロケーター | 入力対象の要素を指定します。                        |
| 入力値     | `{{$json["name"]}}`などのExpressionを利用できます。 |

### クリック

ボタンやリンクをクリックします。PlaywrightのAuto WaitingとActionability Checkを利用します。

| 設定                           |  既定値 | 説明                                                                           |
| ------------------------------ | ------: | ------------------------------------------------------------------------------ |
| ロケーター                     |       - | クリック対象を指定します。                                                     |
| タイムアウト（ミリ秒）         | `30000` | クリック完了を待つ最大時間です。                                               |
| クリック後の待機時間（ミリ秒） |     `0` | 可能な限り固定時間ではなく、状態を指定した待機を使用してください。             |
| ページ遷移を待つ               | `false` | ページ全体の遷移をクリックと同時に待ちます。                                   |
| 強制クリック（上級者向け）     | `false` | Playwrightの安全確認を省略します。必要性を確認した場合だけ有効にしてください。 |

クリック失敗時に自動で強制クリックへ切り替わることはありません。

### 選択肢を選択

HTMLの`select`要素からOptionを選択します。

| 選択方法     | 入力値                   |
| ------------ | ------------------------ |
| 値           | Optionの`value`属性      |
| ラベル       | 画面に表示されるOption名 |
| インデックス | 0から始まるOptionの位置  |

### チェック／チェックを外す

Checkboxをチェックまたはチェック解除します。対象はロケーターで指定します。

### 待機

画面が次の状態になるまで待機します。

| 待機条件                 | 説明                                                                               |
| ------------------------ | ---------------------------------------------------------------------------------- |
| 要素が表示されるまで     | ロケーターで指定した要素が表示されるまで待ちます。                                 |
| 要素が非表示になるまで   | ロケーターで指定した要素が非表示になるまで待ちます。                               |
| テキストが表示されるまで | 指定したテキストが表示されるまで待ちます。                                         |
| URL                      | URLが指定パターンと一致するまで待ちます。例: `**/complete`                         |
| 読み込み状態             | `読み込み完了`、`DOM構築完了`、`通信が落ち着くまで`から選択します。                |
| 指定時間                 | 指定時間だけ固定で待機します。状態ベースの待機が使えない場合だけ使用してください。 |

指定時間以外の待機には**タイムアウト（ミリ秒）**を指定できます。既定値は`30000`です。

### テキストを取得

ロケーターで指定した要素のテキストを取得し、成功出力のトップレベルJSONへ保存します。

```text
出力変数名: registrationNumber
```

出力例:

```json
{
	"success": true,
	"registrationNumber": "A-123456"
}
```

### 属性を取得

要素の`href`、`value`、`src`、`data-id`など、指定した属性を取得します。

| 設定       | 例          |
| ---------- | ----------- |
| 属性名     | `href`      |
| 出力変数名 | `detailUrl` |

### ファイルをアップロード

n8n Binary Dataを`input[type=file]`へ設定します。

1. Google Drive、Read/Write Files from Disk、HTTP Requestなどの前段ノードでBinary Dataを用意します。
2. ファイルをアップロードするステップのロケーターでファイル入力欄を指定します。
3. **入力Binaryフィールド**へ前段ノードのBinary Property名を入力します。既定値は`data`です。

ローカルファイルパスを直接指定することはできません。

### スクリーンショット

スクリーンショットをn8n Binary Dataとして出力します。

| 設定                 | 選択肢／既定値                   |
| -------------------- | -------------------------------- |
| 撮影範囲             | `表示領域`、`ページ全体`、`要素` |
| 画像形式             | `PNG`、`JPEG`                    |
| JPEG画質             | `80`                             |
| 出力Binaryフィールド | `screenshot`                     |

要素を選択した場合は、撮影対象をロケーターで指定します。後続のGmailノードなどで、出力Binaryフィールドを添付ファイルとして利用できます。

## ロケーターの選び方

動的なclass名に依存しない、利用者から見た意味に近いロケーターを優先してください。

推奨順:

1. ロール
2. ラベル
3. テストID
4. プレースホルダーまたはテキスト
5. CSS／XPath（上級者向け）

| ロケーターの種類 | 設定例                                     | 対象                         |
| ---------------- | ------------------------------------------ | ---------------------------- |
| ロール           | ロール: `ボタン`、アクセシブル名: `登録`   | ARIA roleとアクセシブル名    |
| ラベル           | ロケーターの値: `氏名`                     | ラベルに関連付けられた入力欄 |
| プレースホルダー | ロケーターの値: `電話番号を入力`           | Placeholderを持つ入力欄      |
| テキスト         | ロケーターの値: `登録が完了しました`       | 表示テキスト                 |
| テストID         | ロケーターの値: `submit-button`            | `data-testid`属性            |
| CSS              | ロケーターの値: `#customer-name`           | CSSセレクター                |
| XPath            | ロケーターの値: `//button[@type='submit']` | XPath                        |

1つのロケーターが複数要素に一致すると、`ELEMENT_MULTIPLE_MATCH`になります。対象を一意に特定できるロケーターへ変更してください。

## フレーム（iframe）

ロケーターを使うステップにはフレーム設定があります。

| フレーム                | フレームの値               |
| ----------------------- | -------------------------- |
| 指定なし                | 不要                       |
| フレーム名で指定        | iframeの`name`             |
| URLで指定               | iframe URLに含まれる文字列 |
| CSSで指定（上級者向け） | iframe要素のCSSセレクター  |

フレームを指定した後、通常どおりロケーターの種類とロケーターの値を設定してください。

## React／Vue／AngularなどのSPA

SPA内の画面切り替えはページ全体のNavigationを発生させないことがあります。次の構成を推奨します。

1. クリックするステップの**ページ遷移を待つ**を`false`にします。
2. **クリック後の待機時間（ミリ秒）**は`0`のままにします。
3. 直後に待機ステップを追加します。
4. `要素が表示されるまで`、`テキストが表示されるまで`、または`URL`で完了状態を待ちます。

例:

```text
ステップ1: クリック
  ロケーターの種類: ロール
  ロール: ボタン
  アクセシブル名: 登録
  ページ遷移を待つ: false

ステップ2: 待機
  待機条件: 要素が表示されるまで
  ロケーターの種類: テキスト
  ロケーターの値: 登録が完了しました
  タイムアウト: 30000
```

SPAはバックグラウンド通信を続ける場合があるため、`通信が落ち着くまで`よりも、対象要素、テキスト、URLを待つ設定を推奨します。

## Expression

各ItemのJSONをステップ設定から参照できます。

入力例:

```json
{
	"name": "山田太郎",
	"phone": "09012345678",
	"address": "東京都千代田区"
}
```

入力ステップの入力値:

```text
{{$json["name"]}}
```

```text
{{$json["phone"]}}
```

```text
{{$json["address"]}}
```

テキストを取得、または属性を取得で保存した値も、後続ノードから通常のn8n Expressionとして利用できます。

## 再試行

各ステップに再試行を設定できます。

| 設定                 |  既定値 | 説明                                       |
| -------------------- | ------: | ------------------------------------------ |
| 再試行               | `false` | 一時的な失敗を再試行します。               |
| 最大再試行回数       |     `2` | 最初の実行後に追加で試行する最大回数です。 |
| 再試行間隔（ミリ秒） |  `1000` | 再試行間の待機時間です。                   |

再試行対象:

- `ELEMENT_NOT_FOUND`
- `ELEMENT_NOT_VISIBLE`
- `ELEMENT_NOT_CLICKABLE`
- `ELEMENT_TIMEOUT`
- `CLICK_TIMEOUT`
- `NETWORK_ERROR`

入力不正、認証エラー、無効なロケーターなど、再試行しても改善しないエラーは再試行しません。

## 出力

このノードには2つのMain出力があります。

### 出力1: 成功

入力ItemのJSONとBinaryを維持し、`success: true`と取得結果を追加します。

```json
{
	"name": "山田太郎",
	"success": true,
	"registrationNumber": "A-123456"
}
```

### 出力2: エラー

既定の**エラー時の動作: エラーデータを出力**では、構造化されたエラーをエラー出力へ送ります。

```json
{
	"success": false,
	"browserError": {
		"type": "ELEMENT_NOT_FOUND",
		"step": 4,
		"operation": "click",
		"message": "指定された要素が見つかりませんでした。",
		"url": "https://example.jp/customer/new",
		"locator": {
			"type": "role",
			"role": "button",
			"name": "登録"
		},
		"frame": {
			"type": "none",
			"value": ""
		},
		"retryCount": 2,
		"timestamp": "2026-01-01T00:00:00.000Z"
	}
}
```

**エラー時の動作: ワークフローを停止**を選ぶと、n8nのNode Errorとして処理します。ノードの**On Error／失敗しても処理を続行**設定が有効な場合は、そのn8n標準動作を優先します。

## エラー時スクリーンショット

ノード全体の**エラー時にスクリーンショットを取得**を有効にすると、失敗時の画面をPNGでエラー出力のBinary Dataへ追加します。

```text
エラー時にスクリーンショットを取得: true
エラースクリーンショットのBinaryフィールド: errorScreenshot
```

JSONには次の値も追加されます。

```text
browserError.screenshotBinaryProperty = "errorScreenshot"
```

後続のGmailなどで`errorScreenshot`を添付ファイルとして指定できます。LINE、Gmail、SMS、Slackなどへの通知処理はこのノードには含まれないため、エラー出力へ任意の通知ノードを接続してください。

LINE通知のExpression例:

```text
ブラウザ操作でエラーが発生しました。

ステップ: {{$json["browserError"]["step"]}}
処理: {{$json["browserError"]["operation"]}}
エラー: {{$json["browserError"]["message"]}}
URL: {{$json["browserError"]["url"]}}
```

## デバッグモード

**デバッグモード**を有効にすると、成功またはエラーJSONの`debug`へ次の情報を追加します。

- ステップ番号と操作
- ステップの開始、再試行、終了
- 機密情報を除去したURL
- ロケーター情報
- 所要時間
- 再試行回数

Debug情報へPassword、Cookie、Token、Authorization Header、Credentialは出力しません。

## セキュリティ

既定では次の制限があります。

- NavigationはHTTP／HTTPSだけを許可
- URLに埋め込まれたUsername／Passwordを拒否
- localhost、プライベートIP、Link-local、Metadata Endpointを遮断
- RedirectおよびSubresource Requestにも同じネットワーク制限を適用
- Uploadはn8n Binary Dataだけを許可
- Uploadサイズを制限
- ローカルファイルパスを拒否
- 任意JavaScript実行、CAPTCHA突破、Anti-Bot回避は未実装
- Error URLからQuery、Fragment、認証情報を除去

社内システムへ接続する場合だけ**プライベートネットワークURLを許可（信頼済みサイトのみ）**を有効にしてください。この設定を有効にすると、そのワークフローからn8n実行環境が到達できる内部ネットワークへアクセス可能になります。

## 実行環境

### このForkのDocker Image

このForkの標準Docker ImageにはAlpine Chromiumが含まれます。既存の非root `node`ユーザーとして実行し、ノードから`--no-sandbox`は追加しません。

Dockerfile変更を反映するには、Imageを再Buildしてn8nコンテナを再作成してください。

### Docker以外

Chrome、Edge、またはChromiumを標準的な場所へインストールしてください。別の場所にある場合は、n8n管理者が次の環境変数へ絶対パスを設定できます。

```text
N8N_BROWSER_AUTOMATION_EXECUTABLE_PATH
```

この値はワークフロー作成者からは設定できません。

## トラブルシューティング

### BROWSER_LAUNCH_FAILED

- Chrome／Edge／Chromiumがインストールされているか確認してください。
- Docker Imageを変更後に再Buildしたか確認してください。
- カスタム配置の場合は`N8N_BROWSER_AUTOMATION_EXECUTABLE_PATH`を確認してください。

### SECURITY_BLOCKED

- URLがHTTP／HTTPSか確認してください。
- URLにUsernameやPasswordを埋め込んでいないか確認してください。
- 社内サイトの場合は、リスクを確認したうえで**プライベートネットワークURLを許可（信頼済みサイトのみ）**を有効にしてください。

### ELEMENT_NOT_FOUND／ELEMENT_MULTIPLE_MATCH

- ロケーターの文字列が実際の画面と一致しているか確認してください。
- CSSよりロール、ラベル、テストIDを優先してください。
- iframe内ならフレーム設定を確認してください。
- SPAで表示が遅れる場合は、操作前に待機ステップを追加してください。

### ELEMENT_NOT_VISIBLE／ELEMENT_OBSCURED

- Loading OverlayやModalが消えるまで`要素が非表示になるまで`で待ってください。
- **強制クリック（上級者向け）**を安易に有効化しないでください。

### NAVIGATION_TIMEOUT／ELEMENT_TIMEOUT

- 固定待機を長くする前に、適切な待機条件を設定してください。
- SPAでは`通信が落ち着くまで`ではなく、要素、テキスト、URLを待つ設定を推奨します。
- 必要に応じてページ遷移タイムアウトまたは待機のタイムアウトを調整してください。

### ファイルのアップロードが失敗する

- 前段ノードのBinary Property名と**入力Binaryフィールド**が一致しているか確認してください。
- **最大アップロードサイズ (MB)**を超えていないか確認してください。
- ロケーターが`input[type=file]`を一意に指定しているか確認してください。

## Ver.1の対象外

- Browser Recorder
- GUI Element Picker
- AIによるLocator生成
- OCR Element Detection
- 複数ノード間のBrowser Session共有
- Download File操作
- Popup操作
- Firefox／WebKit実行
- Desktop／Windows Native RPA
- 任意JavaScript実行
- CAPTCHA突破／Anti-Bot回避
