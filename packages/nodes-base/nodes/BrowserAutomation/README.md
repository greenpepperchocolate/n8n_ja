# ブラウザ操作

ブラウザ操作は、PlaywrightとChromiumを使ってWeb画面を自動操作するn8nノードです。
APIを持たない業務システムへの入力、登録、結果取得、ファイルアップロード、
スクリーンショット取得などを、1つのノード内に複数のStepとして設定できます。

1回の入力Itemに対するすべてのStepは、同じBrowser ContextとPageで上から順番に実行されます。
そのため、Open URL後のログイン状態や画面状態を、後続のFillやClickでそのまま利用できます。

## クイックスタート

以下は、フォームを開いて氏名を入力し、登録結果を取得する最小構成です。

1. ワークフローに**ブラウザ操作**ノードを追加します。
2. **ブラウザで行う操作**で**操作を追加**を押し、`ページを開く`を選択します。
3. **URL**へ対象画面のURLを入力します。
4. 操作を追加し、`文字を入力`を選択します。
5. **操作する場所の指定方法**を`項目名で指定（おすすめ）`、**探す文字または指定値**を`氏名`にします。
6. **入力する文字**に`{{$json["name"]}}`を入力します。
7. 操作を追加し、`ボタンなどをクリック`を選択します。
8. **クリックする種類**を`ボタン`、**画面に表示されている名前**を`登録`にします。
9. 操作を追加し、`指定した状態まで待つ`で完了メッセージの表示を待ちます。
10. 操作を追加し、`画面の文字を取得`で登録番号を取得します。

`画面の文字を取得`の**取得結果の名前**を`registrationNumber`にした場合、後続ノードから次の式で参照できます。

```text
{{$json["registrationNumber"]}}
```

## 主な機能

- 1ノード内で複数Stepを順番に実行
- Google Sheetsなどの前段ItemをExpressionで利用
- Role、Label、Text、Test IDなどのPlaywright Locator
- React、Vue、AngularなどのSPAに適した状態ベースの待機
- 通常スクロールと無限スクロール
- iframe内の要素操作
- n8n Binary Dataからのファイルアップロード
- PNG／JPEGスクリーンショットのBinary出力
- Step単位のRetry
- 成功／エラーの2系統出力
- 構造化された日本語エラー情報
- エラー発生時のスクリーンショット取得
- Browser、Context、Pageの自動Cleanup

## 実行モデル

- 1回のノード実行につきChromiumプロセスを1つ起動します。
- 入力Itemごとに独立したBrowser ContextとPageを作成します。
- 同じItemのStep間では、Cookie、ログイン状態、Pageを維持します。
- 異なる入力Item間では、CookieやSessionを共有しません。
- 入力Itemは順番に処理されます。
- ノード実行の終了、エラー、キャンセル時にPage、Context、Browserを閉じます。
- Headless OFFの手動実行では、既定で最後の画面を30秒表示してから閉じます。
- Headless OFFの手動実行でエラーになると、ページ右上へ操作番号、操作名、原因、エラー種別を表示してから閉じます。
- 自動ワークフロー、Headless、即時Close設定、キャンセルでは、ブラウザをすぐ閉じます。
- Ver.1では、複数のブラウザ操作ノード間でSessionを共有しません。

## ブラウザ設定

**ブラウザ画面を表示せずに実行**は最初から表示され、既定では無効です。
画面を表示せずに実行する場合は有効にしてください。その他の項目は、**ブラウザの詳細設定（通常は変更不要）**の
**詳細設定を追加**から必要なものだけ追加できます。

| 設定                                                    |       既定値 | 説明                                                                                            |
| ------------------------------------------------------- | -----------: | ----------------------------------------------------------------------------------------------- |
| ブラウザ画面を表示せずに実行                            |      `false` | 画面を表示してChromiumを実行します。Dockerなど画面のない環境では有効にしてください。           |
| 実行後すぐブラウザを閉じる                              |      `false` | 手動実行では成功画面またはエラー内容を指定時間表示します。有効にするとすぐ閉じます。           |
| 実行後に画面を残す時間（ミリ秒）                        |      `30000` | 手動実行の画面を表示する時間です。最大`300000`（5分）です。                                    |
| ブラウザ起動タイムアウト（ミリ秒）                      |      `30000` | Chromiumの起動を待つ最大時間です。                                                              |
| ページ遷移タイムアウト（ミリ秒）                        |      `30000` | URLを開く操作などのページ遷移を待つ最大時間です。                                               |
| 表示領域の幅                                            |       `1280` | ブラウザ表示領域の幅です。                                                                      |
| 表示領域の高さ                                          |        `720` | ブラウザ表示領域の高さです。                                                                    |
| ブラウザの識別情報（上級者向け）                        |           空 | 空の場合はChromiumの既定値を使用します。                                                        |
| 表示言語と地域                                          |      `ja-JP` | ブラウザ内で使用する言語と地域です。                                                            |
| タイムゾーン                                            | `Asia/Tokyo` | Browser ContextのTimezoneです。                                                                 |
| HTTPS証明書エラーを無視（非推奨）                       |      `false` | 信頼できない証明書を無視するかを指定します。通常は無効のまま使用してください。                  |
| 社内ネットワークやlocalhostへのアクセスを許可           |      `false` | localhostやプライベートIPへの接続を許可します。信頼できる社内サイトに限って有効にしてください。 |
| 最大アップロードサイズ (MB)                             |         `25` | 1回のファイルアップロードで許可する最大Binaryサイズです。                                       |

## ステップ

**ステップ**へ操作を追加し、ドラッグして実行順を並べ替えます。

### URLを開く

指定したURLを開きます。

| 設定         | 説明                                                                |
| ------------ | ------------------------------------------------------------------- |
| URL          | 開くHTTP／HTTPS URL。Expressionを利用できます。                     |
| 読み込み待機 | `読み込み完了`、`DOM構築完了`、`通信が落ち着くまで`から選択します。 |

SPAでは、最初の画面表示に`DOM構築完了`を使い、その後に要素の表示を待つステップを置く方法を推奨します。

### 文字を入力

入力欄へ値を設定します。Playwrightの`fill()`を使用します。

| 設定       | 説明                                                |
| ---------- | --------------------------------------------------- |
| 操作する場所 | 入力欄の項目名や画面の案内文で指定します。            |
| 入力する文字 | `{{$json["name"]}}`など前のノードの値も利用できます。 |

### ボタンなどをクリック

ボタンやリンクをクリックします。PlaywrightのAuto WaitingとActionability Checkを利用します。

| 設定                           |  既定値 | 説明                                                                           |
| ------------------------------ | ------: | ------------------------------------------------------------------------------ |
| 操作する場所                         |       - | ボタンなどの種類と画面上の名前で指定します。                                   |
| クリックを待つ最大時間（ミリ秒）     | `30000` | クリック完了を待つ最大時間です。                                               |
| クリック後に追加で待つ時間（ミリ秒） |     `0` | 通常は0のままにし、次に状態を指定した待機を追加してください。                  |
| クリック後のページ切り替えを待つ     | `false` | クリックによって別ページが読み込まれる場合だけ有効にします。                   |
| 強制クリック（上級者向け）     | `false` | Playwrightの安全確認を省略します。必要性を確認した場合だけ有効にしてください。 |

クリック失敗時に自動で強制クリックへ切り替わることはありません。

**クリック後のページ切り替えを待つ**は、ページを切り替えるスイッチではありません。クリックによって別ページが読み込まれる場合に、その読み込み完了を待つ設定です。同じページ内だけが更新される検索画面やSPAでは無効のままにし、直後に状態を指定した待機操作を追加してください。

### プルダウンを選択

HTMLの`select`要素からOptionを選択します。

| 選び方       | 入力値                   |
| ------------ | ------------------------ |
| 表示文字     | 画面に表示される選択肢   |
| HTMLの値     | Optionの`value`属性      |
| 上からの順番 | 0から始まるOptionの位置  |

### チェック／チェックを外す

チェックボックスへチェックを入れる、またはチェックを外します。対象は項目名などで指定します。

### 指定した状態まで待つ

画面が次の状態になるまで待機します。

既定値は**指定した時間だけ待つ**の`1000`ミリ秒です。待機操作を追加した直後は場所の
入力なしで実行できます。特定の画面状態を待つ場合は、目的に応じて別の待機条件へ変更してください。

| 待機条件                 | 説明                                                                               |
| ------------------------ | ---------------------------------------------------------------------------------- |
| 要素が表示されるまで     | 指定した場所が表示されるまで待ちます。                                             |
| 要素が非表示になるまで   | 指定した場所が非表示になるまで待ちます。                                           |
| テキストが表示されるまで | 指定したテキストが表示されるまで待ちます。                                         |
| URL                      | URLが指定パターンと一致するまで待ちます。例: `**/complete`                         |
| 読み込み状態             | `読み込み完了`、`DOM構築完了`、`通信が落ち着くまで`から選択します。                |
| 指定時間                 | 指定時間だけ固定で待機します。状態ベースの待機が使えない場合だけ使用してください。 |

指定時間以外の待機には**待つ最大時間（ミリ秒）**を指定できます。既定値は`30000`です。

### 画面をスクロール

| スクロール方法                                           | 用途                                                     |
| -------------------------------------------------------- | -------------------------------------------------------- |
| 指定した距離だけ移動                                     | 上または下へ指定したピクセル数だけ移動します。           |
| ページの最下部まで移動                                   | 現在のページの一番下まで1回移動します。                  |
| 指定した場所まで移動                                     | 部品名、項目名、CSSなどで指定した場所まで移動します。    |
| 追加データがなくなるまで繰り返す（無限スクロール）       | 最下部への移動と追加読み込みの確認を繰り返します。       |

無限スクロールでは、次の安全設定を使用します。

| 設定                               | 既定値           | 説明                                                                   |
| ---------------------------------- | ---------------- | ---------------------------------------------------------------------- |
| 追加読み込みの確認方法             | ページの高さ     | ページの高さ、または指定した場所の件数が増えたかを確認します。         |
| 最大スクロール回数                 | `50`             | この回数でも追加読み込みが続く場合は、途中成功にせずエラーにします。   |
| 1回ごとの待ち時間                  | `1000`ミリ秒     | 追加データが読み込まれるまで待つ時間です。                             |
| 変化がない場合に終了する回数       | `2`              | 連続して変化しなければ、最下部まで到達したと判断します。               |

商品や投稿の要素数を確認したい場合は、**追加読み込みの確認方法**を**指定した場所の件数が増えるか確認**へ変更し、繰り返し表示される商品カードなどを指定してください。

最大回数に達すると`SCROLL_LIMIT_REACHED`をエラー出力へ返します。無限ループや意図しない長時間実行を防ぐため、成功扱いにはしません。

画面内の独立したスクロール領域を持つサイトは、ページ全体のスクロールでは読み込めない場合があります。実サイトで対象領域の構造を確認してください。

### 画面の文字・リンクを取得

指定した場所の文字、またはリンク先URLを取得し、成功出力へ保存します。

**取得する範囲**で、1件だけ取得するか、表示されているすべてを一覧で取得するかを選べます。

| 取得する範囲                         | 出力             |
| ------------------------------------ | ---------------- |
| 1件だけ取得                         | 文字列                   |
| 表示されているすべてを一覧で取得     | 文字列の配列             |

**取得する範囲**は操作する場所より先に選択します。ブラウザで要素を選ぶと1件用と一覧用のロケーターを両方保存するため、選択後に範囲を切り替えても自動で使い分けます。手動でロケーターを編集した場合は、その編集内容を優先します。

一覧で取得する場合の**最大取得件数**は既定値`100`、上限`1,000`です。非表示の要素は結果に含みません。文字取得では空の文字を、リンク取得ではリンク先URLを持たない要素を結果に含みません。

```text
取得結果の名前: registrationNumber
```

出力例:

```json
{
	"success": true,
	"registrationNumber": "A-123456"
}
```

一覧取得の例:

```text
取得する範囲: 表示されているすべてを一覧で取得
探す文字または指定値: #contents__wrap .Contents__innerGroupBody h3 > span
取得結果の名前: データ
```

```json
{
	"success": true,
	"データ": ["検索結果1", "検索結果2", "検索結果3"]
}
```

### リンクを取得

選択したリンクのURLを取得します。リンク内の文字や画像をブラウザで選択した場合も、最も近いリンクを自動で選択します。

| 設定           | 例          |
| -------------- | ----------- |
| 取得結果の名前 | `detailUrl` |

### ファイルをアップロード

n8n Binary Dataを`input[type=file]`へ設定します。

1. Google Drive、Read/Write Files from Disk、HTTP Requestなどの前のノードでファイルを用意します。
2. ファイルをアップロードする操作でファイル入力欄を指定します。
3. **アップロードするファイルの受取元名**へ前のノードのファイル名を入力します。既定値は`data`です。

ローカルファイルパスを直接指定することはできません。

### スクリーンショット

スクリーンショットをn8n Binary Dataとして出力します。

| 設定                 | 選択肢／既定値                   |
| -------------------- | -------------------------------- |
| 撮影範囲             | `表示領域`、`ページ全体`、`要素` |
| 画像形式             | `PNG`、`JPEG`                    |
| JPEG画質             | `80`                             |
| 画像の保存先名       | `screenshot`                     |

指定した場所だけを選択した場合は、撮影対象を画面の文字や項目名で指定します。後続のGmailノードなどで、画像の保存先名を添付ファイルとして利用できます。

## ブラウザから要素を選択する

場所を指定する操作では、**操作する場所の指定方法**で**ブラウザで選ぶ（おすすめ）**を選ぶとElement Pickerを利用できます。

1. 対象の操作より前に**ページを開く**を追加し、開始URLを設定します。
2. 対象画面までに必要な入力、クリック、待機、スクロールなどを前の操作として設定します。
3. **ブラウザを開いて選ぶ**を押します。対象操作の直前までが自動実行され、選択用ブラウザに対象画面が表示されます。
4. 対象へマウスを重ね、`Alt + クリック`します。`Esc`で選択を中止できます。
5. 要素を再び特定できる指定方法、指定値、画面部品の種類、IFrame経路が操作へ自動設定されます。

Pickerは表示中の文字そのものを指定値として保存しません。選択した要素と実際に同一であり、かつ再実行時にも同じ要素を特定できる候補を次の順に採用します。

1. Test ID
2. ID、属性、クラス、DOM経路から生成したCSS
3. 画面部品の種類と名前
4. 項目名
5. 入力欄の案内文

これらの候補で1件に絞れない場合は、選択した要素までの位置を含む完全なDOM経路をCSSとして設定します。

**画面の文字を取得**と**リンクを取得**では、選択した要素だけに一致する1件用CSSと、同じグループに一致する一覧用CSSを両方保存します。**取得する範囲**を後から切り替えても、要素を選び直す必要はありません。

**リンクを取得**では、リンク内の文字や画像を選択しても、リンク先URLを持つ最も近い要素を保存します。リンクではない場所は選択できません。

通常のクリックは選択用ブラウザ内の追加操作にも使用できます。前段のロケーターが複数要素に一致するなど、自動実行できない操作がある場合は、その時点で自動実行を止めて理由を表示します。選択用ブラウザは閉じないため、そこから通常どおり操作して目的の画面まで進み、要素を選択できます。セキュリティ設定による拒否やブラウザ切断時は選択を中止します。

前段の文字取得、リンク取得、スクリーンショットは画面状態を変えないため、選択用ブラウザでは省略されます。入力Binaryを引き継げないファイルアップロードは自動再現を止め、選択用ブラウザでの手動操作へ切り替えます。

入力欄の値やPasswordは取得しません。IFrame内を選択した場合は、外側から内側までの経路も自動設定します。選択待ちは2分でタイムアウトし、成功、エラー、中止のすべてでPicker用ブラウザを閉じます。

Pickerのブラウザはn8nを実行しているマシンで起動します。Dockerやリモートサーバーなど画面を直接表示できない環境では利用できないため、手動でロケーターを指定してください。

## 操作する場所の選び方

通常はブラウザで対象を選びます。手動で指定する場合は、項目名やボタンの部品名を使うとWebサイトの更新後も壊れにくくなります。

推奨順:

1. ブラウザで選ぶ
2. 画面の部品名で指定
3. 項目名で指定
4. 入力欄の案内文で指定
5. テストID（上級者向け）
6. CSS／XPath（上級者向け）

| 指定方法                   | 設定例                                                         | 対象                         |
| -------------------------- | -------------------------------------------------------------- | ---------------------------- |
| ブラウザで選ぶ             | 選択用ブラウザで対象を`Alt + クリック`                         | 画面上で選択した要素         |
| 画面の部品名               | クリックする種類: `ボタン`、画面に表示されている名前: `登録`   | ボタンなどの種類と表示名     |
| 項目名                     | 探す文字または指定値: `氏名`                                   | 項目名がある入力欄           |
| 入力欄の案内文             | 探す文字または指定値: `電話番号を入力`                         | 入力欄内に案内文がある項目   |
| テストID（上級者向け）     | 探す文字または指定値: `submit-button`                          | `data-testid`属性            |
| CSS（上級者向け）          | 探す文字または指定値: `#customer-name`                         | CSSセレクター                |
| XPath（上級者向け）        | 探す文字または指定値: `//button[@type='submit']`               | XPath                        |

通常の操作で1つの指定が複数の場所に一致すると、`ELEMENT_MULTIPLE_MATCH`になります。**画面の文字を取得**または**リンクを取得**で**表示されているすべてを一覧で取得**を選んだ場合は、複数の一致を配列として取得できます。

旧バージョンで保存された**画面に見えている文字で指定**は引き続き実行できますが、新しい設定では選択できません。固定文字が表示されるのを待つ場合は、**指定した状態まで待つ**の**テキストが表示されるまで**を使用します。

## 埋め込み画面（iframe）

通常のページでは何も追加しません。画面の中に別のWebページが埋め込まれている場合だけ、操作するステップで**IFrameを追加**を押します。この項目はiframe専用です。

| IFrameの見つけ方          | IFrameの指定値            |
| ------------------------- | ------------------------- |
| 名前で指定（おすすめ）    | iframeの`name`            |
| URLの一部で指定           | iframe URLに含まれる文字列 |
| CSSで指定（上級者向け）   | iframe要素のCSSセレクター |

### IFrameが入れ子になっている場合

**IFrameを追加**を繰り返し、外側から内側の順に並べます。順番が違うと対象を見つけられません。

```text
IFrame 1（最も外側）
  見つけ方: 名前で指定
  指定値: customerFrame

IFrame 2
  見つけ方: URLの一部で指定
  指定値: /department

IFrame 3（操作する項目に最も近い）
  見つけ方: CSSで指定
  指定値: #form-frame
```

最後に、通常どおり**操作する場所の指定方法**と**探す文字または指定値**を設定します。入れ子の順番はドラッグで変更できます。

## React／Vue／AngularなどのSPA

SPA内の画面切り替えはページ全体のNavigationを発生させないことがあります。次の構成を推奨します。

1. クリックする操作の**クリック後のページ切り替えを待つ**を`false`にします。
2. **クリック後に追加で待つ時間（ミリ秒）**は`0`のままにします。
3. 直後に待機ステップを追加します。
4. `要素が表示されるまで`、`テキストが表示されるまで`、または`URL`で完了状態を待ちます。

例:

```text
操作1: ボタンなどをクリック
  操作する場所の指定方法: 画面の部品名で指定（おすすめ）
  クリックする種類: ボタン
  画面に表示されている名前: 登録
  クリック後のページ切り替えを待つ: false

操作2: 指定した状態まで待つ
  何を待つか: テキストが表示されるまで
  表示を待つ文字: 登録が完了しました
  待つ最大時間: 30000
```

SPAはバックグラウンド通信を続ける場合があるため、`通信が落ち着くまで`よりも、対象要素、テキスト、URLを待つ設定を推奨します。

## Expression

各ItemのJSONをステップ設定から参照できます。

入力例:

```json
{
	"name": "山田太郎",
	"phone": "09012345678",
	"address": "東京都千代田区"
}
```

入力ステップの入力値:

```text
{{$json["name"]}}
```

```text
{{$json["phone"]}}
```

```text
{{$json["address"]}}
```

文字またはリンクを取得して保存した値も、後続ノードから通常のn8n Expressionとして利用できます。

## 再試行

各ステップに再試行を設定できます。

| 設定                 |  既定値 | 説明                                       |
| -------------------- | ------: | ------------------------------------------ |
| 再試行               | `false` | 一時的な失敗を再試行します。               |
| 最大再試行回数       |     `2` | 最初の実行後に追加で試行する最大回数です。 |
| 再試行間隔（ミリ秒） |  `1000` | 再試行間の待機時間です。                   |

再試行対象:

- `ELEMENT_NOT_FOUND`
- `ELEMENT_NOT_VISIBLE`
- `ELEMENT_NOT_CLICKABLE`
- `ELEMENT_TIMEOUT`
- `CLICK_TIMEOUT`
- `NETWORK_ERROR`

入力不正、認証エラー、無効なロケーターなど、再試行しても改善しないエラーは再試行しません。

## 出力

このノードには2つのMain出力があります。

### 出力1: 成功

入力ItemのJSONとBinaryを維持し、`success: true`と取得結果を追加します。

```json
{
	"name": "山田太郎",
	"success": true,
	"registrationNumber": "A-123456"
}
```

### 出力2: エラー

既定の**エラー時の動作: エラーデータを出力**では、構造化されたエラーをエラー出力へ送ります。

```json
{
	"success": false,
	"browserError": {
		"type": "ELEMENT_NOT_FOUND",
		"step": 4,
		"operation": "click",
		"operationName": "ボタンなどをクリック",
		"message": "指定された要素が見つかりませんでした。",
		"url": "https://example.jp/customer/new",
		"locator": {
			"type": "role",
			"role": "button",
			"name": "登録"
		},
		"frame": {
			"type": "none",
			"value": ""
		},
		"retryCount": 2,
		"timestamp": "2026-01-01T00:00:00.000Z"
	}
}
```

**エラー時の動作: ワークフローを停止**を選ぶと、n8nのNode Errorとして処理します。ノードの**On Error／失敗しても処理を続行**設定が有効な場合は、そのn8n標準動作を優先します。

n8nのエラー画面と選択用ブラウザでは、`操作4（ボタンなどをクリック）でエラーが発生しました。原因：指定された要素が見つかりませんでした。`の形式で表示します。

## エラー時スクリーンショット

ノード全体の**エラー時にスクリーンショットを取得**を有効にすると、失敗時の画面をPNGでエラー出力のBinary Dataへ追加します。

```text
エラー時にスクリーンショットを取得: true
エラースクリーンショットのBinaryフィールド: errorScreenshot
```

JSONには次の値も追加されます。

```text
browserError.screenshotBinaryProperty = "errorScreenshot"
```

後続のGmailなどで`errorScreenshot`を添付ファイルとして指定できます。LINE、Gmail、SMS、Slackなどへの通知処理はこのノードには含まれないため、エラー出力へ任意の通知ノードを接続してください。

LINE通知のExpression例:

```text
ブラウザ操作でエラーが発生しました。

操作: {{$json["browserError"]["step"]}}（{{$json["browserError"]["operationName"]}}）
原因: {{$json["browserError"]["message"]}}
URL: {{$json["browserError"]["url"]}}
```

## デバッグモード

**デバッグモード**を有効にすると、成功またはエラーJSONの`debug`へ次の情報を追加します。

- ステップ番号と操作
- ステップの開始、再試行、終了
- 機密情報を除去したURL
- ロケーター情報
- 所要時間
- 再試行回数

Debug情報へPassword、Cookie、Token、Authorization Header、Credentialは出力しません。

## セキュリティ

既定では次の制限があります。

- NavigationはHTTP／HTTPSだけを許可
- URLに埋め込まれたUsername／Passwordを拒否
- localhost、プライベートIP、Link-local、Metadata Endpointを遮断
- RedirectおよびSubresource Requestにも同じネットワーク制限を適用
- Uploadはn8n Binary Dataだけを許可
- Uploadサイズを制限
- ローカルファイルパスを拒否
- 任意JavaScript実行、CAPTCHA突破、Anti-Bot回避は未実装
- Error URLからQuery、Fragment、認証情報を除去

社内システムへ接続する場合だけ**社内ネットワークやlocalhostへのアクセスを許可**を有効にしてください。この設定を有効にすると、そのワークフローからn8n実行環境が到達できる内部ネットワークへアクセス可能になります。

## 実行環境

### このForkのDocker Image

このForkの標準Docker ImageにはAlpine Chromiumが含まれます。既存の非root `node`ユーザーとして実行し、ノードから`--no-sandbox`は追加しません。

Dockerfile変更を反映するには、Imageを再Buildしてn8nコンテナを再作成してください。

### Docker以外

Chrome、Edge、またはChromiumを標準的な場所へインストールしてください。別の場所にある場合は、n8n管理者が次の環境変数へ絶対パスを設定できます。

```text
N8N_BROWSER_AUTOMATION_EXECUTABLE_PATH
```

この値はワークフロー作成者からは設定できません。

## トラブルシューティング

### BROWSER_LAUNCH_FAILED

- Chrome／Edge／Chromiumがインストールされているか確認してください。
- Docker Imageを変更後に再Buildしたか確認してください。
- カスタム配置の場合は`N8N_BROWSER_AUTOMATION_EXECUTABLE_PATH`を確認してください。

### SECURITY_BLOCKED

- URLがHTTP／HTTPSか確認してください。
- URLにUsernameやPasswordを埋め込んでいないか確認してください。
- 社内サイトの場合は、リスクを確認したうえで**社内ネットワークやlocalhostへのアクセスを許可**を有効にしてください。

### ELEMENT_NOT_FOUND／ELEMENT_MULTIPLE_MATCH

- **探す文字または指定値**が実際の画面と一致しているか確認してください。
- CSSより画面の部品名や項目名を優先してください。
- iframe内ならiframe設定を確認してください。
- SPAで表示が遅れる場合は、操作前に待機ステップを追加してください。

### ELEMENT_NOT_VISIBLE／ELEMENT_OBSCURED

- Loading OverlayやModalが消えるまで`要素が非表示になるまで`で待ってください。
- **強制クリック（上級者向け）**を安易に有効化しないでください。

### NAVIGATION_TIMEOUT／ELEMENT_TIMEOUT

- 固定待機を長くする前に、適切な待機条件を設定してください。
- SPAでは`通信が落ち着くまで`ではなく、要素、テキスト、URLを待つ設定を推奨します。
- 必要に応じてページ遷移タイムアウトまたは待機のタイムアウトを調整してください。

### ファイルのアップロードが失敗する

- 前のノードのファイル名と**アップロードするファイルの受取元名**が一致しているか確認してください。
- **最大アップロードサイズ (MB)**を超えていないか確認してください。
- ファイル入力欄の指定が`input[type=file]`を1つだけ特定しているか確認してください。

- CAPTCHA突破／Anti-Bot回避
